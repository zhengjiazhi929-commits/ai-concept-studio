## 明确禁用的主张

| ID | 禁用说法 | 原因 |
|---|---|---|
| X01 | Agentic Coding 已经可以取代程序员 | 无法被现有证据支持，忽略任务定义、监督和验收 |
| X02 | Vibe Coding 就是低级版 Agentic Coding | 把使用方式与执行架构混为一谈 |
| X03 | 只要能调用工具就是 Agentic Coding | 一次工具调用不足以证明有持续反馈和纠错闭环 |
| X04 | 测试通过就说明代码正确、安全、可上线 | 测试可能覆盖不足或与需求错位 |
| X05 | 沙箱能保证绝对安全 | 沙箱只能约束影响范围，仍有覆盖与绕过风险 |
| X06 | SWE-bench 分数就是实际开发成功率 | 数据、任务、harness 和环境均有限定范围 |
| X07 | 每个 Coding Agent 都会先生成完整计划 | 有的系统显式计划，有的逐步决策 |

## 脚本阶段的事实检查规则

1. 每个数字、日期和具体产品能力必须映射到来源 ID；
2. 每个跨行业判断至少需要两个独立来源或明确标注“本片判断”；
3. 口播中不能把“可以”“部分产品”“在特定环境”删成无条件结论；
4. 教学案例、示意动画和真实产品画面必须在字幕中区分；
5. 发布前重新检查动态文档和产品能力是否有变更。
