## 1. 执行原则

这版不把 Agent 画成抽象角色，也不靠科技感特效解释机制。画面证据主要来自：

1. 可真实运行的本地 SaaS 演示环境；
2. Codex、代码编辑器、终端、测试、Git Diff 和浏览器的真实录屏；
3. 官方资料页面的局部摘录；
4. 明亮的技术编辑部排版、纸张批注和简单线条；
5. 手部、肩后和桌面视角的真实工作场景。

所有本地 SaaS 用户、手机号、客户记录、导出结果和性能数据均使用虚构或程序生成数据。凡出现本地 SaaS 的镜头，界面左上角必须常驻：

**演示环境｜数据虚构**

凡出现 Codex、编辑器、终端、测试或 Diff 的演示任务，左下角显示：

**本地演示工程**

真实产品录屏保持原始窗口结构和真实光标行为，只允许裁切、局部推近、框选、下划线和中文批注。不得制作虚构的产品能力、命令结果或官方界面。

## 2. 素材组件

| 组件 | 用途 | 制作要求 |
|---|---|---|
| ProductCapture | 本地 SaaS 浏览器录屏 | 真实运行、虚构数据、常驻“演示环境｜数据虚构” |
| WorkbenchCapture | Codex、编辑器、终端、测试、Diff、浏览器录屏 | 使用同一个本地演示工程，保持文件名、结果与任务进度连续 |
| StepStrip | 连续任务步骤 | 用 4～6 张真实截图横排或竖排，不使用环形结构 |
| SourceExcerpt | 官方资料摘录 | 保留标题、来源域名和日期；只截必要短句，增加中文标注 |
| ZoomAndHighlight | 解释真实界面 | 局部推近、矩形框、下划线、箭头和放大镜 |
| FlatDiagram | 机制或边界图 | 明亮底色、简单线条、无装饰性空间效果 |
| Checklist | 任务合同、权限、验收、五问 | 真实 Issue、表格或纸面清单样式，逐项勾选 |
| CompareLayout | 两种方式或两个维度 | 左右并列真实界面或截图，不做抽象对撞 |
| WorkScene | 人的参与和责任 | 手部、肩后、桌面实拍，不使用通用机器人或虚拟人物 |
| TaskMatrix | 任务选择矩阵 | 平面坐标、纸笔标注或编辑部图表 |

## 3. 真实演示工程连续性

全片使用同一个“客户管理后台”本地演示项目：

- 角色：管理员、普通用户；
- 功能：批量导出客户；
- 代码区：权限模块、客户数据模型、导出模块、测试目录；
- 数据：全部虚构；baseline 客户列表和同步 CSV 中的邮箱、手机号均为明文，只有验收后的下载 CSV 才脱敏；
- 大数据量：使用程序生成记录，不展示真实个人信息；
- baseline：客户列表正常、导出按钮存在；POST /api/export 对 admin 和 viewer 都同步返回 200 CSV；前端却按异步 JSON 解析，因此页面显示失败；没有 jobId、状态查询或独立下载链路；
- 验收态：admin 创建任务返回 202 和 jobId，可查询 queued、processing、complete 状态并下载脱敏 CSV；viewer 创建、查询和下载均返回 403；
- 交付证据：Git Diff、权限测试、异步任务测试、脱敏检查、回归测试、导出界面、性能记录和风险清单。

官方资料以 02-source-register.md 和 03-claim-ledger.md 为事实边界。优先录制以下页面的标题与必要局部：

- OpenAI：Unrolling the Codex agent loop；
- OpenAI：Harness engineering: leveraging Codex in an agent-first world；
- OpenAI：Running Codex safely at OpenAI；
- Anthropic：Making Claude Code more secure and autonomous with sandboxing；
- SWE-bench 官方页面。
