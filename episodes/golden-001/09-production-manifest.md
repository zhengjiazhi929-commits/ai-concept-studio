## 1. v0.2 制作原则

本期不再以“AI 科技感动态图形”为主，而是用**真实产品行为、可复现的本地实验和官方来源**解释 Agentic Coding。

核心画面配额：

| 类型 | 目标占比 | 本期内容 |
|---|---:|---|
| 真实 UI 与操作录像 | 50% | Codex、代码库、终端、测试、Diff、本地 SaaS 浏览器验收 |
| 官方来源与证据 | 20% | 官方文档、产品说明、研究页面、来源日期与重点摘录 |
| 程序化排版与解释 | 30% | 标题、字幕、来源角标、步骤条、扁平流程图、权限表、任务矩阵、产品五问 |
| AI 生成图像或视频 | 0% | 本期默认不使用 |

制作约束：

1. 真实产品录像必须来自实际运行界面，不用动画伪装成真实产品；
2. SaaS 案例使用虚构客户数据，但页面、接口、测试和导出流程必须真实运行；
3. 真实操作、官方资料与口播主张必须能够互相对应；
4. 08-storyboard.md 继续提供章节、顺序和时间节点，但其“AI 氛围底图”“2.5D 科技图”等视觉描述由本清单覆盖；
5. 94 镜视为剪辑事件，不等于制作 94 个独立动画；
6. 程序化图形只承担解释、标注和统一栏目风格，不抢真实 UI；
7. 不使用数字人，不使用 AI 生成背景，不用霓虹发光、玻璃拟态和无意义粒子；
8. 任何供应商只作为可替换适配器，不把 API Key、Voice ID 或专有项目格式作为节目真源。

## 4. 本地 SaaS 演示项目

### 4.1 项目目的

本地 Demo 用于真实展示“批量导出客户”功能如何从任务进入代码、测试、修复和浏览器验收。它不是商业产品评测，画面固定标注：

> 本地演示环境 / 虚构数据

实际项目路径为 `C:\Users\User\Documents\Codex\2026-07-28\wo\demo\agentic-coding-saas`。项目必须能够在干净环境中重新运行。Codex 负责搭建和维护，创作者不需要手写代码，但必须能够按项目 README 中的步骤启动、恢复检查点和执行验收。

### 4.2 Before 状态

录制前固定一个可重复恢复的 baseline：

- 客户列表页可以正常访问；
- 页面**已经有**“批量导出客户”入口；
- 导出入口调用旧的同步导出接口，但前端按异步任务 JSON 读取响应，因此点击后进入失败状态；
- 管理员与普通用户两个虚构角色可以切换，但后端没有角色保护，普通用户同样可以调用导出；
- 导出内容没有脱敏；
- 导出在请求内同步生成，没有后台任务、任务编号、状态查询或独立下载流程；
- 客户数据全部为虚构数据；
- 验收测试共 5 项，基线结果为 **1 项通过、4 项失败**；
- 通过项仅证明客户列表使用本地虚构数据；其余权限、异步任务、脱敏下载与任务级权限测试失败；
- Git baseline commit 为 `d3ef196`，正式录制前工作区应保持干净并指向该提交；
- README 记录启动、测试和浏览器访问方式。

必须录制：

1. Git clean 状态和 baseline commit `d3ef196`；
2. 正常显示客户列表且已经存在导出按钮的 Before 页面；
3. 点击导出后，旧同步响应无法满足前端异步 JSON 处理而显示失败；
4. 基线验收测试的真实结果：5 项中 1 项通过、4 项失败；
5. 代码中无角色保护、无脱敏、同步导出的三个基线问题；
6. 管理员与普通用户在基线中都能发起导出请求的实际权限缺口。

### 4.3 验收条件

任务合同至少包含：

- 管理员可以发起客户批量导出；
- 普通用户不能导出客户数据；
- 手机号等敏感字段按规则脱敏；
- 大批量导出不应让页面长时间无响应；
- 原有客户列表与权限功能不回归；
- 交付 Diff、测试结果、浏览器行为和剩余风险说明。

具体实现可以简化，但口播中出现的每个可视化结论都必须有真实演示或明确标注为“概念解释”。不得用假进度条代替未实现的性能行为。

### 4.4 真实失败与修复

需要保留一条真实的“红测到绿测”证据链：

1. 执行与验收条件对应的测试；
2. 显示真实失败输出；
3. Codex 读取错误、定位代码并修改；
4. 重新执行相关测试；
5. 执行必要的回归测试；
6. 最终得到真实通过结果。

本期无需人为制造失败：baseline commit `d3ef196` 上的验收测试已经真实呈现 1 项通过、4 项失败。录像应保存这次基线运行及其原始输出，再记录 Agent 根据反馈修复后的结果。

为了补拍，保存四个 Git 检查点：

| 检查点 | 作用 |
|---|---|
| `baseline` | commit `d3ef196`；旧同步接口、无角色保护、无脱敏、无后台任务，5 项测试中 1 通过/4 失败 |
| `first-pass` | 第一次实现或验收测试仍失败的状态 |
| `fixed` | 修复后相关测试通过的状态 |
| `final` | 回归、浏览器验收和证据整理完成 |

如镜头来自检查点复现而非连续首次录制，应在资产记录中标注 `recreated_from_checkpoint: true`，不能暗示它是一次未剪辑的完整执行。

### 4.5 After 与浏览器验收

必须录制以下真实结果：

- After 页面保留既有批量导出入口，但点击后能够正确创建并跟踪异步导出任务，而不是解析旧同步响应后失败；
- 管理员发起导出并得到实际文件或任务结果；
- 普通用户请求被拒绝；
- 导出内容中的敏感字段被脱敏；
- 页面在较大数据量下仍可继续操作，或明确显示异步任务状态；
- 关键回归场景仍正常；
- 最终 Git Diff 与测试结果可以审阅；
- 未解决风险和演示限制明确列出。

浏览器验收录像应把实际点击、页面反馈和结果文件连成完整短链，不用字幕替代未发生的交互。

## 8. 声音与旁白

### 8.1 优先级

声音是降低“批量 AI 内容感”的关键，建议顺序：

1. 创作者本人录制，AI 只做降噪、修音、响度和字幕；
2. 经创作者本人明确授权的个人音色；
3. 自然、克制的通用授权音色，并进行人工停顿和重音审核。

禁止克隆没有明确授权的真人声音。节目只保存内部 `voice_alias`，不保存供应商 Voice ID。

### 8.2 音频产物

- 分段旁白 `audio/segments/VO-xxx-v01.wav`；
- 无音乐母带 `narration-master.wav`；
- 最终混音 `mix-master.wav`；
- 声音配置 `voice-profile.json`；
- 专有词表 `pronunciation.csv`。

规格：

- 48kHz、24-bit WAV、单声道；
- 每段约 8～20 秒；
- 建议语速约每分钟 250～280 个汉字；
- 保留自然呼吸、句间停顿和认知转折；
- 检查 Agentic Coding、Vibe Coding、SaaS、Diff、Harness、Git、CSV 的读音；
- 最终混音约 -14～-16 LUFS，True Peak 不高于 -1 dBTP。

### 8.3 可替换声音接口

```text
voice.produce(text, voice_alias, pace, emotion)
→ wav_path, timing_path, provider_metadata
```

本人录音时，接口输入改为原始录音和脚本文本；授权音色或 TTS 时，供应商返回内容统一转换为本地 WAV 与 `word-timing.json`。同一输入使用内容哈希缓存。

## 9. 字幕

标准真源为 `captions.json`，SRT 与 ASS 由它导出。

必须交付：

- `word-timing.json`；
- `captions.json`；
- `captions.srt`；
- `captions.ass`。

规则：

- 最多两行，每行约 12～16 个汉字；
- 按语义切分；
- 字幕位于平台安全区内，不遮挡真实 UI 的关键按钮和输出；
- 以短语淡入，不做逐字蹦跳；
- 每条最多强调一至两个词；
- 专有词、数字、中英混排和产品版本必须人工校对；
- 中央结论或官方来源原文出现时，普通字幕可以暂时隐藏；
- 真实界面已有大量文字时，字幕应移动或简化，不能压在代码和测试结果上。

## 10. 音乐与音效

- 使用克制的编辑部节拍、轻打击乐或纪录片底乐；
- 不使用“未来科技宣传片”式持续上升音和密集电子音效；
- 优先一条可循环、带低中高能量层级的无歌词主题；
- 密集口播时音乐比旁白低约 18～22dB；
- 测试失败、重点框选、证据勾选和章节切换可使用少量反馈音；
- 音效不能代替必要信息；
- 所有音乐和音效保存授权证明、曲目编号、来源和 cue sheet。

## 12. 低代码执行流程

创作者只需处理以下人工入口：

1. 审核脚本、验收条件和来源；
2. 启动本地 Demo 并参与真实操作录制；
3. 选择本人声音或授权音色；
4. 审核素材选段、隐私清理、预览和终版。

其余机械工作由 Codex 执行。

### 阶段 A：准备 Demo 与证据

- 建立或校验本地 SaaS Demo；
- 写入 acceptance criteria；
- 登记并校验 baseline commit `d3ef196`，随后建立 first-pass、fixed、final 检查点；
- 跑通 Before、失败、修复、After 和浏览器验收；
- 将官方来源映射到主张台账。

### 阶段 B：生成采集队列

- 从 08-storyboard.md 自动生成 `capture-queue.yaml`；
- 将每个镜头标记为 `product_ui`、`official_source` 或 `editorial_layout`；
- 为真实素材生成采集配方；
- 标出需要人工登录、批准和隐私检查的操作。

### 阶段 C：真实录制

- 先录完整实际流程，不为镜头频繁中断；
- 再从 Git 检查点补拍特写；
- 录制 Before/After、失败/修复、Diff、测试和浏览器验收；
- 采集官方资料整页与重点区域；
- 每批素材完成后立即登记版本、日期和隐私状态。

### 阶段 D：声音、字幕与粗剪

- 制作最终旁白；
- 生成词级时间和字幕初稿；
- 自动挑选与口播时间匹配的真实素材候选；
- 对真实 UI 自动裁切、推近、框选和统一尺寸；
- 用程序化模板补足定义、流程、来源、矩阵和五问；
- 输出带镜头号和来源 ID 的低清预览。

### 阶段 E：人工审核与终版

- 第一轮只审事实、真实操作顺序和来源；
- 第二轮审节奏、画面可读性和声音；
- 第三轮在真实手机上进行有声与静音检查；
- 修订后自动混音、转码和生成 QA 报告；
- 人工签字后输出母版与上传版。

## 13. 首期人工与长期自动化边界

| 工作 | 首期 | 稳定后 |
|---|---|---|
| 技术事实与核心观点 | 人工批准 | 始终人工批准 |
| Demo 验收条件 | 人工批准，Codex 实现 | 复用模板，人工批准差异 |
| 本地 Demo 启动与测试 | Codex 辅助，人工观察 | 一键脚本与健康检查 |
| 浏览器操作 | 首期人工录制 | 可重复部分自动录制 |
| Codex/IDE/终端录制 | 人工控制 | 使用采集配方，仍保留人工 |
| 官方来源选取 | 人工确认 | 自动推荐，人工批准 |
| 来源截图与裁切 | 自动初稿，人工复核 | 自动为主，限定条件抽查 |
| 本人录音 | 人工录制 | 人工录制，自动清理和分段 |
| 授权音色或 TTS | 人工试听 | 固定声音别名，自动生成 |
| 字幕和时间对齐 | 自动初稿，人工复核 | 自动为主，英文和数字抽查 |
| 真实 UI 裁切与高亮 | Codex 执行，人工确认 | 根据配方自动执行 |
| 程序化排版 | 首期定模板 | 数据驱动复用 |
| 音乐、混音和转码 | 自动执行，人工听审 | 自动执行，异常报警 |
| 隐私与密钥检查 | 自动扫描 + 人工逐镜 | 始终双重检查 |
| 最终发布 | 人工批准 | 始终人工批准 |

适合长期自动化：采集任务生成、浏览器可重复操作、媒体转码、竖屏裁切、局部推近、来源角标、字幕、排版、混音和技术 QA。

不应完全自动化：真实素材是否足以支持主张、产品 UI 是否被误解、来源裁切是否丢失限定条件、隐私清理、声音表达和最终发布。

## 14. 可替换供应商和工具边界

系统只依赖抽象能力：

```text
voice.produce()
alignment.align()
capture.normalize()
capture.crop_and_highlight()
renderer.render()
audio.mix()
qa.inspect()
```

每个适配器必须：

- 使用标准 WAV、PNG、MP4、JSON、YAML 和 CSV；
- 不把密钥、账号、Voice ID 或专有参数写入节目真源；
- 记录工具、产品与模型版本、执行日期和内容哈希；
- 支持缓存、超时、重试和回退；
- 保留原始素材、清理版和最终选段；
- 更换声音、渲染或编辑工具时，不重写脚本、字幕、采集配方和场景数据；
- 浏览器自动化失效时，可以回退到人工采集而不阻断其余流程。

## 15. 输出规格

### 15.1 快速审阅版

- 540 × 960；
- H.264、低码率；
- 叠加镜头号、来源 ID、Demo 检查点和版本水印；
- 用于事实、素材与节奏审核。

### 15.2 存档母版

- 1080 × 1920、30fps；
- ProRes 422 LT 或等价高质量中间编码；
- 48kHz PCM；
- 无平台水印；
- 保留烧录字幕版和无烧录字幕版。

### 15.3 上传版

- 1080 × 1920、30fps；
- H.264 High，约 12～20Mbps；
- yuv420p；
- AAC 48kHz，256kbps 或以上；
- 文件名包含节目编号、脚本版本、Demo 版本和成片版本。

### 15.4 证据存档

除成片外还必须保留：

- 原始连续录屏；
- 清理后的选段；
- Demo Git 检查点与测试日志；
- 官方来源原始截图、URL 和采集日期；
- Diff、测试、浏览器验收和限制说明；
- 隐私复核与最终签字记录。
