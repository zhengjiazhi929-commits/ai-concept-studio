# 技术机制简报

## 一句话机制

Agentic Coding 的核心不是一次生成，而是让模型在一个受控执行系统中反复完成：**观察当前状态 → 选择行动 → 调用工具 → 接收真实反馈 → 对照目标判断 → 修正或交付**。

## 六层系统模型

| 层 | 系统需要什么 | 典型内容 | 缺失后的结果 |
|---|---|---|---|
| 1. 目标层 | 明确要完成什么 | 任务、约束、验收条件、停止条件 | Agent 可能把错误目标执行得很完整 |
| 2. 上下文层 | 知道与任务相关的事实 | 代码库、Issue、文档、规范、历史变更 | 找错文件、违反团队规范或基于过期信息行动 |
| 3. 决策循环 | 根据当前状态选择下一步 | 拆解、计划、反思、改计划、升级给人 | 退化成一次回答或机械重复 |
| 4. 工具层 | 能改变和检查外部世界 | 搜索、文件编辑、终端、测试、浏览器、Git、API | 模型只能建议，无法验证真实结果 |
| 5. 执行反馈层 | 返回可观察的真实结果 | 编译器、测试、Lint、类型检查、CI、界面状态 | 只能靠模型自我判断“应该可以” |
| 6. 治理层 | 约束可行动范围 | 沙箱、权限、网络策略、日志、预算、审批、回滚 | 自治范围不清，风险与责任不可控 |

第 3～5 层形成执行闭环；第 6 层决定它能否安全地用于真实工作。

## 核心循环

```text
目标 + 约束 + 验收条件
          ↓
读取相关上下文 → 选择下一动作 → 工具在环境中执行
       ↑                         ↓
       └──── 诊断与修正 ← 获取真实反馈
                                ↓
                         对照验收条件
                         ↙            ↘
                  未通过/不确定          已通过
                  重试、改计划、          证据包
                  回滚或询问人              ↓
                                      人工最终验收
```

## 什么才算形成 Agentic 闭环

本片采用四个最低判断条件：

1. **多步推进**：系统能连续决定下一步，不要求人每一步都重新发起；
2. **环境反馈**：能读取工具或运行环境的结果，而非只看自己生成的文本；
3. **依据结果修正**：失败后能诊断、改动作或升级给人，而非只重复同一请求；
4. **明确结束方式**：达到验收条件、触发停止规则或把决策交还给人。

会生成代码不等于 Agentic Coding；会调用一次工具也不一定形成闭环。

## 与相邻概念的二维关系

不把四个词硬排成一条进化链，而分成两个维度：

- **系统维度**：一次建议 ←→ 可在环境中连续执行并验证；
- **人的维度**：严谨检查过程与证据 ←→ 主要凭结果和体验继续提示。

因此可以存在：

- 非 Agentic + 严谨：人逐次审查代码补全；
- 非 Agentic + Vibe：把聊天生成的代码直接复制运行；
- Agentic + 严谨：Agent 执行，但有测试、Diff、权限与人工审批；
- Agentic + Vibe：一句话让 Agent 做应用，几乎不检查过程。

这解释了为什么 Agentic Coding 不是简单的“Vibe Coding 2.0”，但两者又可能重叠。

## 失败恢复不是无脑重试

| 反馈类型 | 合理动作 |
|---|---|
| 临时网络或工具错误 | 有上限地重试，并记录次数与成本 |
| 测试失败 | 读取失败信息，定位原因，修改后重跑相关测试 |
| 需求歧义 | 暂停并向人提出具体问题 |
| 高风险操作 | 停在权限闸门前，请求批准 |
| 反复失败或预算耗尽 | 回滚到检查点，交还人工并附已尝试记录 |

## 贯穿案例如何进入闭环

“增加批量导出客户”首先被转换成任务合同：管理员权限、字段脱敏、十万行数据、回归测试、仅测试环境。Agent 再寻找权限模块、数据模型与既有导出模式，修改和运行测试。当发现普通用户仍可导出时，它读取失败测试与调用链，修正权限中间件并重验。若需要数据库迁移，则生成方案但停在执行前等待批准。最后交付 Diff、测试结果、权限检查和未解决风险，而不是只显示“完成”。

## 机制边界

- 模型不会天然知道隐性业务规则，规则必须被提供或通过人确认；
- 上下文可能过期、缺失或包含恶意指令；
- 测试只验证被写成测试的部分；
- 长动作链会累积小错误、成本和延迟；
- 工具和权限越强，潜在影响范围越大；
- 不同模型在不同 harness 和环境中的表现不可直接互换。
