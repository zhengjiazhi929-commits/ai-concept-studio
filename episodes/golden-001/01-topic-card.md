# 黄金样例 001｜选题卡

- 状态：脚本已通过；视觉 v0.1 被否决，两个去 AI 化候选样张等待选择
- 概念：Agentic Coding
- 工作标题：**Agentic Coding 到底是什么？AI 为什么开始从“写代码”变成“交付任务”？**
- 目标观众：懂 LLM、Prompt、Agent 基础概念，但不以写代码为主业的 AI 产品经理及技术邻近岗位
- 预计时长：10～11 分钟
- 内容类型：近期热门概念解析，不做单一产品发布复盘

## 为什么现在讲

近期创作者围绕 Codex、Claude Code、Jules、Vibe Coding、Coding Agent 和真实任务评测持续产出。单个产品只是热度入口，背后共同的概念变化是：AI 编程的工作单位正从“生成代码”转向“在环境中推进并验证一项任务”。

热度证据与候选排序见：`research/2026-07-31-hot-concept-candidates.md`。

## 这期要替观众解决的问题

看完后，观众应能：

1. 区分代码补全、聊天式编程、Vibe Coding 与 Agentic Coding；
2. 用“目标—行动—反馈—修正—验收”判断一个产品是否真的形成 Agent 闭环；
3. 理解模型之外，工具、运行环境、权限、测试与恢复机制为何同样重要；
4. 判断哪些软件任务适合授权给 Coding Agent；
5. 为 Agentic Coding 产品设计验收条件、权限闸门和结果指标。

## 核心命题

> Agentic Coding 的关键变化，不是 AI 一次写了更多代码，而是工作单位从“代码片段”升级为“可验证的任务”。

辅助对比判断：

> Agentic 与否，主要描述系统如何执行任务；Vibe 与否，主要描述人如何监督和验收。它们不是同一条轴线，也可以同时存在。

这是本账号用于产品分析的**工作定义**，不是声称行业只有一种统一定义。该对比只用于澄清边界，不作为本期主叙事。

## 贯穿案例

给已有 SaaS 管理后台增加“批量导出客户”功能：

- 只有管理员可用；
- 手机号等敏感字段必须脱敏；
- 支持十万行数据而不阻塞页面；
- 补齐测试，不能破坏旧功能；
- 只能部署到测试环境，生产部署必须人工批准。

同一句“加个导出按钮”，可以被处理成一次代码生成，也可以被处理成一项带约束、执行轨迹和验收证据的任务。案例用来展示两者的差别，而不是伪造真实产品实验。

## 内容边界

### 会讲

- 多步任务闭环；
- 工具、代码库与真实环境反馈；
- 失败诊断、重试、改计划与升级给人；
- 沙箱、最小权限、审批、日志与回滚；
- 任务级评测与产品指标。

### 不会讲

- 某款 Coding Agent 的安装或横评；
- “一句话做应用”的纯演示；
- 编程教程或代码逐行讲解；
- “程序员将被取代”一类无法验证的结论；
- 把单一 benchmark 分数等同实际开发成功率。

## 与热门内容的差异

热门内容常展示产品、速度、代码量和最终页面。本期重点补足容易被省略的中间层：任务定义、环境、执行轨迹、失败恢复、权限和验收证据。

## 主要风险

1. **概念尚无绝对统一定义**：明确采用工作定义，并用多家产品的共同机制交叉验证；
2. **标题可能让人误以为二者互斥**：正文第一分钟说明二者是不同维度、可以重叠；
3. **案例可能被误认为实测**：明确标注为教学案例；
4. **厂商材料容易过度泛化**：产品事实只用于证明具体能力，行业结论必须跨来源；
5. **过度乐观**：加入长链可靠性、测试错位、安全、成本和环境差异等限制。
