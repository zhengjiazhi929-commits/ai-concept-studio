# 章节大纲 v0.1

- 标题：**Agentic Coding 到底是什么？AI 为什么开始从“写代码”变成“交付任务”？**
- 预计时长：10 分 30 秒～11 分钟
- 核心概念：Agentic Coding
- 核心承诺：让观众会定义、会识别、会判断是否值得采用
- 贯穿案例：给已有 SaaS 后台增加“批量导出客户”功能

## 叙事主线

整期只讲一个变化：

> AI Coding 的工作单位，正在从“生成一段代码”扩大为“在约束下推进一项可验证的任务”。

全片回答三个问题：

1. 什么才算 Agentic Coding？
2. 它靠什么机制连续完成任务？
3. AI 产品经理应该把任务放权到哪一步，又凭什么验收？

## 关键认知转折

### 第一次：0:15

“两边都会写代码，但只有一边在推进任务。”

### 第二次：4:50

“真正决定能不能进入生产的，往往不是模型，而是模型外面的系统。”

### 第三次：7:25

“Agent 输出的代码越多，不一定越高效，也可能只是把更多工作转移给审查者。”

## 视觉母题

全片反复回到同一条闭环：

```text
目标 → 读取环境 → 采取行动 → 观察结果 → 修正 → 验证
 ↑                                                ↓
 └────────── 继续 / 询问人 / 交付证据 ──────────┘
```

每出现一个风险，就标记闭环中相应的位置：

- 上下文错误：读取环境；
- 工具越权：采取行动；
- 无脑重试：修正与停止条件；
- 测试不足：验证；
- 无法审计：交付证据。

## 节奏规则

- 不从发展史或厂商发布讲起；
- 产品名只作为跨产品例子，不连续罗列；
- Vibe Coding 对比控制在 20 秒以内；
- 每 60～90 秒让 CSV 案例推进一步；
- 架构只保留五个易记词：上下文、工具、状态、验证、控制；
- benchmark 只用于说明“任务级评测与真实能力仍有距离”，不展示榜单；
- 结尾交付五问决策卡，不做空泛的行业预测。

## 结尾五问卡

1. **任务单位是什么？** 建议、补丁，还是完整任务？
2. **它能操作什么？** 文件、命令、网络、依赖与生产环境分别有什么权限？
3. **什么算完成？** 测试、页面行为、性能、业务规则还是人工验收？
4. **哪里必须停下来问人？** 越权、安装依赖、删除数据、提交或部署前？
5. **失败后如何恢复？** 是否有日志、Diff、检查点、预算上限和回滚？
