# 黄金样例执行流程 v0.1

黄金样例采用“人工编排、AI 协作、人类审批”。它不是要求创作者独自手工完成，也不是让尚未开发的系统自动运行。

## 1. 角色分工

Codex 负责：

- 搜集候选选题与一手来源；
- 生成选题卡；
- 整理证据包和事实主张；
- 分析技术机制与产品影响；
- 生成并修改大纲、脚本和分镜；
- 辅助创建图表、素材、配音和初版成片；
- 记录过程、版本、耗时和返工原因。

创作者负责：

- 审批选题与角度；
- 审批关键事实和产品判断；
- 加入个人观点与表达偏好；
- 审批脚本；
- 验收成片并决定是否发布。

正式选题前只创建候选卡，不提前填充黄金样例目录。

## 3. 执行步骤与审批点

### 步骤 A：候选发现

输入：

- 最近 30～45 天一手发布；
- GitHub、Hugging Face、论文等采用信号；
- 博主人工观察卡；
- 账号定位与选题规则。

输出：

- 5 张候选选题卡；
- 每张卡的评分、来源、风险和推荐角度。

审批点 1：创作者选择一个选题，或要求换角度。

### 步骤 B：研究与证据

输出：

- 来源登记表；
- 事实主张台账；
- 技术机制简报；
- 产品影响简报；
- 不确定信息列表。

审批点 2：创作者确认关键结论和个人判断。

### 步骤 C：大纲与脚本

输出：

- 章节大纲；
- 第一版脚本；
- 技术审稿意见；
- 产品视角审稿意见；
- 修改后的定稿候选；
- 事实与脚本映射。

审批点 3：创作者完成表达与观点定稿。

### 步骤 D：分镜与生产

输出：

- 时间轴分镜；
- 架构图和信息图清单；
- 录屏清单；
- AI 素材提示词；
- 配音、字幕和音乐配置；
- 初版视频。

审批点 4：创作者验收成片。

### 步骤 E：复盘

记录：

- 每一步耗时；
- 人工修改的类型和原因；
- 模型最容易出错的部分；
- 重复劳动；
- 适合最先自动化的环节；
- 发布后的内容表现。

## 4. 黄金样例完成标准

- 通过 `docs/02-quality-rubric.md` 的发布线；
- 所有关键事实可追溯；
- 四个审批点均有记录；
- 从选题到成片的全部产物齐全；
- 能明确列出下一阶段最值得自动化的 3～5 个步骤；
- 后续 Agent 可以使用该样例作为固定回归测试。
