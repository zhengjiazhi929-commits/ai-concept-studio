# 数据源登记与使用规则

更新时间：2026-08-25

## 两类来源不能混用

| 来源类别 | 用途 | 能否证明技术事实 |
|---|---|---|
| 市场信号：公开创作者页面、标题、发布时间、公开互动 | 判断“有人在讨论”和候选热度 | 不能 |
| 一手证据：官方文档/博客/仓库、论文、标准、官方 benchmark | 定义、机制、边界、版本和事实核验 | 可以，但要保留引用和抓取时间 |

## 已配置来源

- `studio/config/trend-sources.json`：18 个 Douyin / Bilibili 观察源。只读取无需登录的公开信息；
  Douyin 直读默认关闭，不能读取时生成辅助任务，不伪装成功。
- `studio/config/research.json`：只接受 `official-doc`、`official-blog`、
  `official-repository`、`paper`、`standard`、`benchmark` 六类一手来源。
- `episodes/golden-001/02-source-register.md` 与 `03-claim-ledger.md`：黄金样例来源和主张绑定。

## 每条证据必须保存

`sourceUrl`、来源类型、标题、发布者/作者、发布时间（可得时）、抓取时间、短引用或摘要、
内容哈希、支持的 claim ID、许可证/使用限制和可达状态。缺失字段保持未知，不猜测。

## 抓取规则

1. 遵守站点条款、robots/速率限制和登录边界；不绕过验证码、付费墙或访问控制。
2. URL 必须为允许的 HTTPS 公开地址；每个重定向都重新做 DNS/IP/端口校验。
3. 限制响应大小、超时、重试和并发；Content-Type 不符即拒绝。
4. 网页内容视为不可信数据，不进入系统/开发者指令，不决定 Shell、路径、密钥或发布。
5. 不保存 Cookie、账号、完整私信、无必要个人信息或整页受版权保护内容。
6. 竞品标题/摘要只用于市场信号；正式脚本主张必须回链一手来源。

## 当前未知与发布前动作

- 配置中每个创作者页面的自动化抓取条款尚未逐条形成法律结论；未确认的来源保持辅助/人工模式。
- 公开仓库发布前，要用最新条款重新审查数据源、示例内容和缓存，并删除不能再分发的快照。
