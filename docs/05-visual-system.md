# 长视频视觉系统 v0.2

> 状态：**Canonical / 当前制作标准**  
> 视觉方向：**B — 真实产品纪录片**  
> 生效日期：2026-08-03  
> 适用范围：抖音 8～12 分钟 AI 概念解析长视频  
> 核心受众：理解 AI 基础概念、关注产品落地的 AI 产品经理及技术邻近人群  
> 决策来源：用户确认选择“真实产品纪录片”；本版完全替代并废止 v0.1。

## 1. 核心定位

这套视觉系统不把 AI 包装成未来幻想，而是让观众看见：一个概念如何在真实产品、真实界面和真实任务中发生。

关键词：**明亮、中性、真实、清楚、克制、有证据**。

视觉可信度的优先级：

1. 真实产品录屏与真实操作；
2. 可核验的界面、文档、日志和结果；
3. 真实人物肩后、手部或工作现场素材；
4. 为解释关系而制作的扁平图表；
5. 纯装饰氛围素材。

氛围素材不承担事实表达。每个画面都应至少完成一项任务：证明、解释、比较、定位或推进叙事。

## 2. 明确禁用项

以下表达从默认资产库中移除，不得作为封面、章节页、机制图或转场的常规语言：

- 深色科技背景；
- 霓虹、辉光、光晕和发光描边；
- HUD、雷达、扫描线、数据雨和粒子隧道；
- 发光圆环、悬浮玻璃卡片和透明玻璃界面；
- AI 大脑、机器人头、人形芯片等抽象 AI 图腾；
- 泛蓝紫渐变及无语义的“科技蓝”；
- 伪造产品功能的生成式 UI；
- 用 AI 生成的人物代替真实人物实拍；
- 与叙事无关的机房、宇宙、机器人和抽象网络氛围镜头。

**AI 氛围素材默认关闭。** 只有在脚本明确需要类比、且不能被误认成事实或真实界面时，才可单独申请使用；其时长不得超过成片的 5%，并应在素材台账中标注“示意画面”。

## 3. 画布与安全区

- 画布：1080 × 1920，9:16，30fps；
- 核心信息区：X 72～900，Y 150～1580；
- 右侧至少避让 180px，防止被抖音互动按钮遮挡；
- 底部 300px 不放标题、关键数据、操作步骤或来源；
- 画面顶部 150px 不放必须被完整读取的信息；
- 单屏只承担一个核心结论，同屏最多三个信息层级；
- 横向产品界面进入竖屏时，优先做局部裁切、顺序放大和细节特写，不直接缩成无法阅读的完整桌面。

默认画面结构：

- 上部：短章节名或当前步骤；
- 中部：真实界面、真实操作或扁平图表；
- 下部安全区内：中文动态字幕；
- 左下：必要时显示来源、版本和日期。

## 4. 色彩系统

整体以白、灰、黑为主，橙色只标记“当前动作或当前重点”。

| 角色 | 色值 | 用途 |
|---|---|---|
| 中性白 | `#F7F7F5` | 主背景、说明页 |
| 浅灰 | `#ECEDEA` | 区块分隔、扁平面板 |
| 深灰 | `#202124` | 主文字、主线条 |
| 中灰 | `#737773` | 次文字、非当前步骤 |
| 行动橙 | `#E56B2F` | 当前动作、重点框、步骤进度 |
| 通过绿 | `#3E8B57` | 已验证通过的结果 |
| 错误红 | `#C94D45` | 真实失败、阻断和风险 |
| 审批黄 | `#C58A20` | 需要人类确认或等待审批 |

规则：

- 一屏最多一个强调色，状态对照页可同时使用橙、绿、红；
- 橙色不能用作大面积背景；
- 绿色只用于有证据的通过状态，不装饰性使用；
- 错误红只在真实错误、越权或未通过时出现；
- 产品原始界面色彩不强行重染，外部标注遵循本系统色彩。

## 5. 字体与中文优先

推荐字体：

- 中文标题：思源黑体 Heavy / HarmonyOS Sans SC Bold；
- 中文正文与字幕：HarmonyOS Sans SC Medium；
- 英文、数字和 UI 注释：Inter；
- 代码、路径和终端片段：JetBrains Mono。

字号基准：

- 封面主标题：76～92px，最多两行；
- 章节标题：54～66px；
- 核心判断：48～58px；
- 图表标题：36～42px；
- 图表正文：30～36px；
- 动态字幕：44～50px；
- 来源、版本与日期：23～27px。

中文是叙事主语言。英文概念首次出现时采用：

`Agentic Coding｜智能体式编程`

后续优先使用中文简称；英文产品名、按钮名和代码保持原样。不得为了营造技术感而堆叠英文。

## 6. 真实素材语言

建议单期素材占比：

- 55%～70%：真实产品 UI、录屏、文档、代码差异、日志和测试结果；
- 15%～25%：真实人物肩后、手部、键盘、会议讨论或工作台素材；
- 10%～20%：扁平图表、步骤轨道、中文结论页；
- 0%～5%：经明确批准的示意氛围素材。

### 6.1 产品录屏

- 使用真实产品和可复现的演示任务；
- 保留点击、输入、等待、报错、重试和结果，不伪造“瞬间完成”；
- 关键操作使用原速；等待时间可压缩，但需用时间跳切表达；
- 每次只放大一个关键区域，使用 2px 行动橙描边；
- 录屏中的敏感数据、账号、密钥和私人项目必须在剪辑前处理；
- 不能用生成图片模拟真实产品界面或测试结果。

### 6.2 真实人物与工作现场

- 优先拍摄肩后操作、手部输入、观看结果、讨论和确认等自然动作；
- 人物镜头用于建立真实场景和人机关系，不做“盯着漂浮界面”的摆拍；
- 镜头明亮、自然光或柔和中性光，不加蓝紫灯带；
- 若使用版权允许的真实库存素材，需登记来源；
- 不使用 AI 生成人物冒充实拍。

### 6.3 扁平图表

- 白或浅灰底，深灰线条，行动橙标记当前节点；
- 使用方框、箭头、时间线、表格和状态标签，不使用球体、光环和 3D 节点；
- 图表中文字必须可编辑，不在图片生成模型中生成；
- 一屏不超过 6 个节点，复杂关系分镜展开；
- 图表的职责是解释真实素材中看不清的关系，不取代真实证据。

## 7. 字幕系统

- 默认不超过两行，每行约 12～16 个汉字；
- 按语义短语切分，不按固定字数机械断句；
- 中文字幕为主，英文术语只在首次出现或必须对应 UI 时保留；
- 字幕使用深灰字配中性白实底，或白字配深灰实底；不得使用玻璃模糊底；
- 当前关键词可使用行动橙，但每条字幕最多突出一个词组；
- 以短语为单位直接出现或轻微淡入，不做连续逐字弹跳；
- 字幕比语音提前约 2 帧出现，句尾保留 6～10 帧；
- 中央结论大字出现时，普通字幕暂时隐藏；
- 字幕不得覆盖鼠标点击位置、报错内容、测试结果和来源信息。

## 8. 纪录片剪辑与动效

节奏来自任务推进、真实反馈和观点切换，不依赖装饰特效。

- 普通镜头平均 3～6 秒；
- 每 15～25 秒切换一次视觉模式：录屏、人物、图表或结论页；
- UI 操作以硬切、局部推近、匹配剪辑和短淡化为主；
- 关键操作框进入时间：180～260ms；
- 扁平步骤推进：300～450ms；
- 结论定格：1.2～1.8 秒；
- 同时运动的对象不超过两个；
- 鼠标、输入、测试和错误反馈保留真实运动轨迹；
- 失败后回到前一步，应通过镜头和步骤轨道真实呈现，不使用红色发光回弹；
- 音效以点击、键盘、翻页、提示音和环境声为主，避免科幻升调和能量音效。

## 9. 来源、版本与日期

真实产品纪录片必须让观众区分“事实画面、当前产品状态和解释性示意”。

外部产品 UI、官方文档截图、公开演示或数据画面首次出现时，在左下角显示：

`来源：产品/机构｜页面或版本｜截取日期 YYYY-MM-DD`

自制演示录屏显示：

`演示环境：产品名/版本｜示例项目｜录制日期 YYYY-MM-DD`

要求：

- 来源角标至少完整停留 2 秒；
- 产品更新频繁时必须记录版本、模型名或页面日期；
- 裁切不得改变原始语义；
- 解释性图表标注“示意”；
- 所有来源与素材文件同步登记到单期素材台账；
- 无法确认来源或版本的画面不得作为事实证据。

## 10. 可复用模板

### A. 真实任务开场

用 8～15 秒快速建立问题：需求文档、产品界面、一次真实操作和最终结果各一个镜头。最后落下中文核心问题。

### B. 一句话定义页

中性白底、黑色粗标题、一个行动橙短横线。只保留英文概念、中文名称和一句定义，不放抽象 AI 插图。

### C. 主录屏 + 步骤轨道

主区域展示真实操作；左侧竖排步骤，当前步骤变为行动橙。横向桌面 UI 通过局部裁切推进，禁止整体缩小后长时间展示。

### D. UI 证据特写

冻结真实界面，局部推近目标区域，使用 2px 橙色方框与一条中文旁注。一次只解释一个证据。

### E. 扁平机制图

白底、深灰框线、行动橙当前节点。适合解释 Agent Loop、工具关系、权限路径和验证关系。复杂流程拆成连续镜头。

### F. 权限 / 验收面板

左侧列出自动允许、需要审批、禁止三类权限；右侧列出功能、测试、回归、成本、人工接管和审计证据。状态使用平面标签，不使用仪表盘 HUD。

### G. 人物过渡镜头

肩后观看屏幕、手部操作、停下确认、与同事讨论。用于章节转场和强调“人仍负责目标、审批与验收”。

### H. 结论与产品清单页

中性白底，以一个中文判断加 3～5 条产品问题收尾。条目逐项出现，不用动画图标庆祝。

## 11. 本期 Agentic Coding 的表现标准

本期不使用发光 Agent Loop。用一条可见的真实任务纪录呈现：

`收到需求 → 生成计划 → 检查项目 → 修改文件 → 运行测试 → 发现失败 → 调整方案 → 再次测试 → 输出变更与证据`

执行方式：

- 主画面是“批量导出客户数据”示例的真实演示录屏；
- 左侧步骤轨道显示当前所处阶段；
- 报错、重新规划和再测试必须真实出现；
- 权限请求使用原生审批界面或扁平中文标签解释；
- 测试结果、代码差异和最终交付物作为“任务完成”的证据；
- 用肩后或手部镜头表现人类提出目标、处理审批和最终验收；
- 章节结论落在真实画面之后，而不是用抽象 AI 图像替代过程。

## 12. 长期维护规则

- 每期最多新增一个专属视觉组件，其余优先复用；
- 新组件必须符合明亮中性、真实证据和扁平解释三项原则；
- 产品名称只作为案例与来源出现，不成为无关品牌露出；
- 真实 UI 更新后，应同步更新录屏与版本标注；
- 封面、章节页、字幕、步骤轨道、来源角标和结论页保持位置稳定；
- 每期成片复盘“哪些画面提供了证据，哪些只是装饰”，逐步删除无作用素材；
- 若后续需要调整视觉方向，必须创建新版本并记录决策，不覆盖本版历史。

## 13. 出片前检查

- 是否有任何霓虹、HUD、发光环、玻璃卡片或 AI 大脑残留？
- 是否使用了生成式 UI 或 AI 人物冒充真实素材？
- 每个产品画面是否可读，并记录来源、版本和日期？
- 是否至少呈现一次真实操作、真实反馈和真实验收证据？
- 是否包含自然的肩后、手部或工作现场镜头？
- 横向 UI 在手机竖屏上是否仍能看清关键区域？
- 中文字幕是否完整避开 UI 证据和抖音控件？
- 图表是否保持扁平、中文优先且没有多余装饰？
- 失败、重试和审批是否被真实呈现，而非用特效替代？
- 关闭声音后，观众是否仍能理解当前步骤和核心结论？
