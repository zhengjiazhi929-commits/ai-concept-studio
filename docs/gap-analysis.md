# 目标差距分析

更新时间：2026-08-25

## 结论

项目已经越过“只有脚本”的原型阶段，但尚未越过“可验收 M1”。主要差距不是多写几个
Agent，而是把安全失败路径、工程门禁、真实媒体和人工决定连成一条可恢复证据链。

| 目标 | 审计基线 | 本轮技术整改目标 | 退出证据 |
|---|---|---|---|
| 固定输入生成真实视频 | 截图与六镜有，旧研究/脚本/分镜状态不构成当前人审证据，当前有效旁白和 MP4 无 | 依次重批研究、当前短脚本与分镜，再做本地离线旁白 + Remotion MP4 | Gate 记录、可播放文件、manifest、哈希 |
| 五道人审 | 五 Gate 结构有 | 每次批准重绑当前字节、版本、机器报告 | 操作员审计记录 |
| SSRF / 路径安全 | 第二批边界不完整 | DNS/IP/redirect、realpath/symlink fail closed | 攻击型回归测试 |
| Provider 中断恢复 | 能冻结，不能裁决 | 鉴权人工对账；确认已提交或确认无可复用提交的路径可审计 | 恢复测试与演练 |
| 上传原子性 | 文件与状态可能竞态 | 暂存、CAS 提交、冲突清理/隔离 | 竞争与崩溃测试 |
| 审计可信度 | 写入有 hash-chain，读取未强校验 | 读写均验证且损坏拒绝 | 篡改测试 |
| Prompt 可追溯 | Worker 提示词散落 | 独立文件、稳定 ID/version/hash、运行绑定 | Prompt 漂移测试 |
| CI / 运行时 | 审计基线无 CI、版本范围宽 | 当前已定义精确 Node/pnpm、frozen install、测试、render、安全门禁并通过本地等价命令；hosted 首跑待 push 后执行 | workflow、当前本地结果、后续 hosted 运行链接 |
| 依赖安全 | 已知 high 门禁未关闭 | audit fail-closed，升级/override 有证据 | 0 个 high 或明确阻断 |
| 评测准入 | 离线参考证据，admission=false | 签名/append-only 基础设施；无真实 shadow 不升级 | 可信签名、链验证、人工发布决定 |
| 回滚 | 设计存在，演练不足 | 临时数据根真实演练 mode/状态/媒体恢复 | 可复现演练报告 |
| 开源准备 | 缺许可证/模板/发布材料 | M1 前只记录阻断，不冒充已发布 | 发布阶段另行验收 |

## 业务优先级

1. 先关闭“会泄密、打内网、重复扣费或绕过人审”的风险。
2. 再让任何新提交都必须经过可复现 CI 和固定运行时。
3. 然后核验 `golden-001` 每个上游批准；当前依次停在研究、脚本、分镜 Gate。
4. 当前研究、脚本和分镜都重新批准后才生成旁白，并停在素材/声音 Gate；收到该人工批准后才渲染和 QA。
5. 完成真实成片后再停在最终 Gate。
6. 最终批准、合并 main、发布是三件不同的决定。

## 本轮明确不自动完成

- 不调用付费或外部生成 Provider。
- 不代表 Zhengjiazhi 批准任何 Gate。
- 不把测试通过推导成内容事实正确、业务验收或发布。
- 不自动从 `shadow` 升级到 `assisted` / `active`。
- 不自动合并 `main`、push、部署或公开发布。
