# 逐拍执行与编辑估算时间轴

## 开始条件（2026-09-13）

- 目标：把已批准原文对应的编辑分镜变成可复算、可逐帧执行的新版本；解决只有动作描述、没有执行与时间轴的问题。
- 范围：声明式对象/事件模型、纯函数状态解析、现有 Remotion 接入、估算字幕及受控本地入库/重审。原文、来源与原批准记录不改。
- 非目标：不生成配音、不调用计费 API、不替人审、不启动 live 成片渲染、不提交或推送 Git。
- 风险：R2 动画/字幕；R3 入库与审批哈希。沿用现有 Capability、不可变文件、CAS 与五道人审，不放宽阈值。
- 验收：源对象在复制后仍存在；纳入状态必须在副本完全进入后出现；未触发事件不能泄露未来状态；临时覆盖、会话重置与永久记录相互独立；连线正交；正文无装饰图标且四边清晰。估算时码按整数帧累加，不伪装为音频实测。
- 输入：当前批准脚本与编辑分镜仅用于作品制作。所有自动化测试采用合成内容及临时数据根，禁止 live Episode 进入 Fixture。
- 时间假设：每秒 5.5 个有效字符，逗/顿/冒/分号停顿 0.14 秒，句/问/叹号停顿 0.32 秒；保留原文单元，字幕展示可归一化段落空白；不缩放凑目标时长。结果为 editorial-estimate，audioAligned=false。
- 回滚：旧 cue-only 入口与渲染路径保留；新合同验证失败即拒绝入库/审批，停止在分镜门禁；已有不可变版本不覆盖。
- 环境：源 HEAD `0c2b1cdc993a8c9492ab5a091573d673ac60503d`，分支 `codex/topic-discovery-workflow-20260909`；在独立 clone 叠加当前未提交源码后实施，保留全部已有修改；源码同步逐文件校验基线哈希。

## 可复用执行约束

- `editorial-timing.mjs` 按原文单元顺序编译整数帧；支持拆并镜头，不可丢字、改写批准原文或调整比例凑时长。每镜 12–60 秒、全片 12–24 镜、每镜最多 8 条字幕；字幕为无框短句。以上均为编辑估算，配音后必须重新对齐。
- `editorial-motion.mjs` 分离对象身份、位置和状态。复制保留原件；副本经正交移动进入明确容器后才能纳入；保存前必须检查通过。临时覆盖不修改存储原件；停用只停止召回，不伪称删除。历史压缩只允许保留目标、约束、未决问题的受限转换，不能任意生成或保存改写。
- `editorial-motion-render-model.mjs` 与受控入库共用几何模型。入库在事件前、中、后、字幕起点和镜头尾帧预检；拒绝安全区外、文本不足空间、无关对象碰撞和箭头穿过第三方对象。窗口和存储容器使用可见四边，正文卡片沿用已确认的微磨砂材质；状态文字占独立空间，不叠盖正文。
- `editorial-motion-preview.jsx` 在现有 `ConceptPreview` 内按全局帧渲染；Logo 使用原批准序列连续播放。无计时器、随机播放或 CSS 动画；合成验证只使用临时 fixture 和受控公开素材。
