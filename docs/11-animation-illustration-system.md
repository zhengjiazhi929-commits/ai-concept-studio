## 要解决什么

视频需要让观众看懂“对象发生了什么变化、为什么变化、结果是什么”。
卡片适合归纳事实和并列比较；插画适合解释载入、传递、筛选、匹配、检查、恢复等过程。
不能把“文字卡片进场”或“标题前增加图标”算作过程插画。也不按每隔几秒必须放插画的比例机械拼装。

例如解释按需加载，要能看到哪些材料没有进入上下文、哪份内容被复制进去，以及加载前后状态。
仅展示“目录 → 上下文”的箭头不够；装饰性人物、机器人或夸张容器也不会自动改善解释。

## 分层与当前实现边界

1. **语义定义**：`illustration-system-contract.mjs` 定义解释目标、事实声明 ID、对象、动作和检查点。
   对象类型为 document / database / context / packet / version / comparison；动作包括
   select / transfer / reveal / query / compare / restore。每个动作必须指向实际对象与声明，且处于时间范围内。
2. **可复用对象**：`illustration-system/components.jsx` 提供文件、上下文窗口、数据包、数据库、标签及正交连线。
   图形对象的尺寸、标签、记录、选中状态可参数化；它们单独表达对象，不放在卡片标题前作装饰。
3. **动作状态**：`scene-state.mjs` 根据帧计算动作进度、位置、可见性和当前值。
   输入相同帧必须得到相同结果；不使用随机数、计时器、CSS animation 或 transition。
4. **叙事示例**：`catalog.mjs` 提供三种动作模式及合成示例数据，12 秒/段。
   当前不是任意脚本自动生成动画的通用编排器，也尚未接入 Kernel 的生产决策与资产批准流程。
5. **渲染证据**：独立 proof runner 生成不可覆盖候选、MP4、关键帧、离线画廊、Git HEAD 和源码/媒体哈希。
   所有候选的 productionApproved / userAccepted / finalAccepted 固定为 false；本阶段没有“自行批准”接口。

## 制作流程

脚本阶段先写清本段要解释的变化；分镜阶段选择卡片、对比或过程插画。
需要插画时先查对象库和动作模式；不足时新增候选组件，不在具体某期视频里堆临时 SVG 特判。
生成关键动作预览，人工确认表达与风格，再考虑扩充资产库及对接生产流程。
制作完整视频时仍要经过原研究、脚本、分镜、资产/声音、最终验收门禁。

样式确认只批准明确版本与示例覆盖的用法，不意味着以后任何排列组合都无需看图。
不同主题、内容长度、长宽比或背景变化需要重新做适配检查；三段 16:9 样例不证明竖屏可用。

## 一致性与绘制要求

- 颜色沿用仓库的浅薄荷背景、深色正文、薄荷强调；紫色仅用于差异/待处理状态，不额外创建彩虹色盘。
- 同级对象使用一致线宽、圆角、文本层级。内容卡片保持完整、可见四边框及纯文字标题。
- 图形占位由解释任务决定；标题与关键说明优先可读，不为了放大图案缩小文字。
- 图案要可识别且可解释：数据库代表存储、文件代表内容、数据包代表传递中的值。
  不用指南针替代路由、人物替代决策；需要“比较”就显示实际差异。
- 表达归属/容纳时，内容必须实际进入目标范围；复制时保留来源，不能靠遮挡制造已移动的假象。
- 连线只能横竖及直角转弯，端点要对齐对应对象；去程、回程不要交叉绕乱。
- 输出、完成、反馈状态不能在对应动作发生前出现。先输入、再处理、后结果；最终保持可读停留。
- 正式视频与独立预览均复用现有 approved-v013 连续旋转 logo；不改变右上角尺寸和位置。
- 不包含人物、临时粒子封面、卡片标题内图标、覆盖文字的完成勾或付费生成资产。
- 用户此前选中的液态玻璃材质图片不等于全局生产材质已实现；本阶段不静默改变旧视频卡片材质。

## 三个待确认示例

| 预览 | 必须看懂的变化 | 不能出现的错误 |
| --- | --- | --- |
| 选中并加载 | 只复制命中内容，其他材料留在原处，抵达后显示已载入 | 全部塞入、提前宣布完成、图标远离所属对象 |
| 请求与返回 | 请求条件匹配数据行，然后将该行结果返回调用方 | 先有结果再查询、结果与查询编号不符、只画单向流程 |
| 校验与恢复 | 定位实际差异，从已知版本恢复，当前内容真的改变 | 只改标题/颜色、未定位就恢复、完成勾遮挡内容 |

## 验证和交付

从 `studio/` 运行：

```sh
node --test tests/illustration-system-*.test.mjs
node scripts/render-illustration-system-proof.mjs --stills-only
taskpolicy -b nice -n 20 node scripts/render-illustration-system-proof.mjs
```

渲染以本机可用运行时与工具为准，concurrency=1。每次新建输出目录，不覆盖旧视频。
代表帧为 0/75/150/225/300/359；代表帧不能代替连续播放，尤其要检查移动途中和状态切换。
MP4 是无旁白动作样片，不是最终真人录音、不等于完整成片。

专项测试证明时间、引用、确定性及绑定失效规则；ffprobe 证明编码/时长等媒体事实。
人工观看需要另外确认：语义是否清楚、动作是否真实连续、布局有无遮挡、文字是否清楚、logo 是否旋转。
视觉问题必须对应实际 MP4 时间点；“无已知机器错误”不表述为“人工视觉通过”。
