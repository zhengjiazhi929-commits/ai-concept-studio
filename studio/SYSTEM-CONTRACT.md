# AI Concept Studio 系统合同 v0.1

> 本文件定义产品与一期生产合同，不声明当前实现或发布完成度。当前状态只看
> [`../docs/STATUS.md`](../docs/STATUS.md)。

## 目标

把近期热门 AI 技术概念转化为面向 AI 产品经理的 8～12 分钟竖屏知识视频，并保留事实来源、人工审批、可复现素材和质量报告。

## 系统边界

- Agent 可以搜集、整理、起草、编排、渲染和检查；
- 人必须决定选题，并依次批准研究、脚本、分镜、素材（含旁白）和最终成片五道闸门；选题决定不重复计入审批闸门；
- 第一版只在本机运行，不自动发布；第三方密钥只允许保存在 Git 忽略的本机 `.env.local`，不得写入结构化产物、日志或接口响应；
- 所有一期内容都写入独立目录，失败后可以从最近状态继续；
- 竞品内容只作为热度信号，一手来源才可以支撑技术主张；
- 视频中的真实产品画面、测试和结果不得由生成式 UI 冒充。

## 一期数据真源

每一期只有一个 `episode.json`，记录：

- 主题、受众与核心命题；
- Agent 流水线状态；
- 五道人工审批状态、审批版本和完整决定历史；
- 来源文档与内容哈希；
- 场景、字幕、素材和时间轴；
- 渲染输出、QA 结果和已知限制。

Markdown、图片、音频和视频仍是独立文件，`episode.json` 只保存相对路径和元数据。

## 系统级热点雷达

热点概念发现发生在创建具体一期内容之前，因此它有独立的数据域：

- `data/trends/signals.json` 保存可追溯的创作者市场信号；
- `data/trends/latest.json` 保存最近一次聚类、门槛和排名结果；
- `data/trends/selection.json` 保存人工选中的 Research Agent 输入；
- 竞品信号不能进入事实证据包，除非其内容本身指向并可核对一手来源；
- 观察池、事件主导项和已经制作的概念不能绕过后端门槛进入研究阶段。

## 创作者信号采集

- 采集器只读取无需登录的公开页面，不保存 Cookie、账号令牌或私有接口参数；
- 平台无法程序直读时必须生成 Codex 辅助任务，不能把网页外壳记为成功；
- 采集失败、待复核和过期观察不能覆盖已有可用信号，也不能参与热点排名；
- 每条入库信号必须保留创作者、来源链接、发布时间、观察时间和采集批次；
- 公开互动数据可以记录，缺失字段必须保持缺失。

## 研究与事实证据

- 人工选择正式候选后，系统创建一期草稿，热点信号与事实证据继续保存在不同数据域；
- Research Agent 只能把官方文档、官方博客、官方仓库、论文、标准和原始基准登记为事实来源；
- 网页可达性、HTTP 状态与内容哈希不能替代语义核验，来源必须记录支持事实、定位信息和适用边界；
- 关键主张必须覆盖定义、机制、能力边界和产品影响，且不能存在未解决的关键冲突；
- 证据未达到配置门槛时，系统必须保持 blocked 状态，不能让人工界面绕过后端批准研究结论；
- 未配置模型供应商时生成 Codex 辅助任务，不伪装为已经完成自动研究。

## Agent 接口

```text
agent.run(episode, context)
→ status, artifacts, findings, nextAction, requiresApproval
```

Agent 不能直接跨越人工闸门。驳回必须填写意见，旧版本和旧审批记录不得删除；系统只从被驳回阶段重新生成，并使所有下游审批失效。替换素材或旁白同样必须使下游渲染、QA 和成片审批失效。

模型调用的固定失败策略为：可重试故障下，主通道首次调用失败后最多重试两次，即主通道共 3 次；随后备用通道只尝试 1 次。明确的无额度、无权限、无效密钥或模型不可用错误不在同一通道重复请求，而是直接进入备用通道。仍失败则把尝试日志写入一期状态并暂停等待人工处理。失败不得覆盖上一版可用产物。进程意外退出后，遗留的 `running` 状态必须在下次启动时恢复为可重试的 `failed` 状态。

## 五道人工审批

1. `research`：研究证据达到来源、主张、交叉核验和关键类别门槛；
2. `script`：脚本事实、结构和表达可进入分镜；
3. `storyboard`：时间轴、字幕、证据场景和素材提示可进入制片；
4. `assets`：必需素材均已登记，来源与版权可核验，旁白可试听；
5. `final`：渲染成片先通过技术与内容 QA，再由人终审。

## 完成标准

系统第一阶段只有同时满足以下条件才算打通：

1. 黄金样例可以导入为结构化一期数据；
2. 控制台能读取状态、运行模块并显示日志；
3. 真实素材能生成一个竖屏 MP4；
4. 自动 QA 能核对尺寸、时长、编码和必需文件；
5. 重新启动后仍能读取原状态和输出；
6. 未配置模型或声音供应商时，系统明确显示等待配置，不伪装完成。
7. 热点候选能说明来自哪些独立创作者、哪些维度缺失，以及为什么通过或未通过门槛。
8. 采集批次能区分程序直读、Codex 辅助、待复核、过期与失败状态，并能从历史批次恢复。
9. 人工选题能创建一期研究草稿；研究证据未达到来源、主张、交叉核验和关键类别门槛时不能批准研究结论。
10. AI 生成必须使用结构化输出、版本化保存、限制单期调用次数，并对可重试故障严格执行主通道 3 次、备用通道 1 次、失败后人工介入的策略。
11. 最终 QA 必须同时通过技术检查与内容检查；证据场景未绑定真实素材、字幕断层或正式样片未配置旁白时不能通过。
12. 控制台必须能切换 AiHubMix/OpenAI 主通道、上传逐项素材与旁白、批准或带意见驳回五道闸门，并显示当前版本。
## 视觉样片审核检查点

视觉样片是完整成片之前的设计验证产物，不得伪装成 `final` 最终成片，也不得扩展为第六道生产 Gate。系统把它登记在 `reviewCheckpoints.visualProof`：机器检查必须绑定版本化视频、渲染清单、设计 QA 报告、对比图及其 SHA-256；只有机器检查通过后才能记录人工批准。任何证据变化都会使实时验证失败，但不会改写 `approvals.final`、完整成片渲染记录或既有五道人工闸门。
