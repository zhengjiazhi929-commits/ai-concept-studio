# 热点概念发现 Agent v0.1

## 它解决什么问题

这个 Agent 不追逐单条新闻，也不凭一个博主的选题做决定。它把多个 AI 创作者近期内容视为“市场信号”，寻找面向 AI 产品经理值得解释、并且已经出现独立创作者共振的技术概念。

输出不是脚本，而是一个候选池。只有通过正式门槛并经人工选择的概念，才会进入 Research Agent。

## 数据流

```text
创作者公开内容
→ 标准化信号
→ 创作者覆盖去重
→ 概念归一化与聚类
→ 事件降噪、概念独立性检查
→ 硬门槛与已知维度评分
→ 正式候选 / 继续观察 / 观察池
→ 人工选择
→ Research Agent
```

### 输入一：观察源

`config/trend-sources.json` 保存创作者名称、平台、受众匹配度、信号权重和 `coverageGroup`。

这些来源由 `COLLECTOR-AGENT.md` 描述的双通道采集流程更新：可直读页面由程序处理，其余来源生成 Codex 辅助任务。

`coverageGroup` 用于处理同一个人跨平台、同一机构多个账号等重复覆盖。一个组在一个概念里最多计一次独立创作者。

### 输入二：标准化信号

`data/trends/signals.json` 中每条信号至少包含：

```json
{
  "id": "creator-date-topic",
  "creatorId": "creator-id",
  "title": "公开视频标题或可核对摘要",
  "sourceUrl": "https://...",
  "publishedAt": "2026-08-01T00:00:00+08:00",
  "observedAt": "2026-08-03T00:00:00+08:00",
  "datePrecision": "page-date",
  "angle": "definition",
  "conceptIds": ["agent-skill"]
}
```

相对日期或人工审计窗口必须在 `datePrecision` 中标明。页面没有公开播放量、互动量或评论样本时，不写对应字段。

### 输入三：概念词典

`config/concept-taxonomy.json` 定义概念名称、别名、上位概念、跨产品案例、影响的产品决策，以及后续研究应寻找的一手来源。

新增概念不能只填一个热词。至少需要：

- 脱离某个品牌后仍然成立；
- 两个及以上跨产品案例；
- 两个及以上会受影响的产品决策；
- 至少一种可核验的一手资料类型。

## 候选门槛

正式候选必须同时满足：

1. 14 天内至少 3 个独立创作者组覆盖，或 30 天内至少 5 个；
2. 不是由新闻、发布会等事件型内容占主导；
3. 通过概念独立性检查；
4. 已知维度归一化分达到 70；
5. 尚未进入过视频生产。

快速观察通道要求 7 天内至少 2 个独立创作者组，且两者相对各自历史中位表现均达到 1.8 倍。没有创作者历史基线时不会启用这条通道。

## 评分解释

满数据时共 100 分：

- 独立创作者覆盖：35
- 目标受众匹配度：20
- 相对创作者自身表现：20
- 近期增长速度：15
- 评论中的问题密度：10

如果互动或评论数据缺失，对应维度标记为不可用，不记零分，也不填造数据。系统用“已得分 / 可用分”展示已知信息，并单独给出高、中、低置信度。

因此，“已知维度 68/70”不等于掌握了 97 分的完整数据；它表示当前可核验的 70 分里获得 68 分，同时置信度会因为缺少另外 30 分的数据而下降。

## 候选池

- `formal_candidate`：通过全部正式门槛，可以人工选入研究阶段。
- `continue_watching`：出现共振或快速增长，但仍有条件不完整。
- `observation_pool`：创作者覆盖不足、事件占主导或概念尚不独立。
- `already_covered`：已经制作或进入生产的概念，不占用新一期推荐位。

后端也会校验池状态，不能通过接口把观察项直接送入研究阶段。

## 当前结果快照

截至 `2026-08-03` 的首份快照包含 51 条信号、18 个创作者覆盖组。当前正式候选依次包括：

1. Agent Skill
2. Context Engineering 与 Agent Memory
3. MCP
4. Agent Evaluation
5. 按任务与成本选择模型

Agentic Coding 已被识别为黄金样例主题，因此归入 `already_covered`。

这些排名只代表当前市场信号，不代表技术事实或最终选题结论。选择后，Research Agent 仍必须回到官方文档、论文和原始项目核验。

## 怎样更新

1. 把新一轮公开观察保存为 `data/trends/snapshots/<日期>-<说明>.json`。
2. 运行 `pnpm import:trends -- <文件名>`；同一信号 ID 会更新，不会重复累加。
3. 运行 `pnpm trends`，或在控制台点击“运行热点发现 Agent”。
4. 在界面查看创作者覆盖、事件占比、数据缺口与置信度。
5. 只对正式候选点击“选为研究候选”。选择结果写入 `data/trends/selection.json`。

未来的定时采集器可以逐条调用本地接口 `POST /api/trends/signals`。采集器只负责提供可追溯的标准化信号，候选逻辑仍由同一套引擎执行。

## 当前限制

- 尚未自动登录平台，也不绕过平台访问限制；首版信号来自可公开访问页面与人工审计快照。
- 目前多数公开页面没有稳定的单条互动数据，所以相对爆款和评论问题密度经常不可用。
- 标题归一化主要依靠概念词典和明确概念 ID；新术语仍需要维护词典。
- 当前选择会写出 Research Agent 输入并创建一期草稿；运行 Research Agent 后生成研究计划和辅助任务，但完整事实证据仍需核验和人工批准。
