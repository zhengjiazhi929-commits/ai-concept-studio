# 创作者信号采集 Agent v0.1

## 目标

把创作者近期公开内容稳定地转换成热点雷达可以读取的标准化信号，同时保留来源、时间精度、采集方式和失败原因。

它不负责判断技术事实是否正确。竞品内容只说明“市场正在讨论什么”，后续 Research Agent 必须回到官方文档、论文或原始项目。

## 为什么采用双通道

不同平台的公开页面结构不同：

- B站视频页在普通公开请求中包含标题、发布时间和公开互动数据，可以程序直读；
- 抖音精选作品列表依赖客户端渲染，普通请求通常只能拿到网页外壳，作品列表需要 Codex 的网页读取能力辅助；
- 任何读取失败都会留下明确状态，不会写入虚构标题、日期或互动量。

因此系统使用：

```text
程序直读公开页 ─┐
                 ├→ 标准化观察 → 概念词典匹配 → 去重入库 → 热点雷达
Codex 辅助读取 ──┘
```

这不是绕过平台限制的抓取器，不登录账号、不保存 Cookie，也不调用未授权的私有接口。

## 一次采集会产生什么

运行 `pnpm collect` 或点击控制台中的“运行信号采集 Agent”后，会产生：

- `data/collector/latest.json`：最近一次采集的结果和每个来源状态；
- `data/collector/runs/<批次>.json`：不会被下一次覆盖的历史记录；
- `data/collector/source-health.json`：每个来源最近一次尝试、成功方式和失败原因；
- `data/collector/assist-task.json`：需要 Codex 继续读取的来源、页面链接、搜索建议和批次模板；
- `data/trends/signals.json`：通过日期与概念检查后的标准化信号；
- `data/trends/latest.json`：有新信号时自动重新计算的热点候选。

## 信号进入雷达前的门槛

一条采集观察只有同时满足以下条件才会入库：

1. 创作者在观察源配置中；
2. 有公开来源链接和可解析发布时间；
3. 发布时间没有超出 45 天采集窗口；
4. 标题能匹配概念词典，或者 Codex 批次明确给出了概念 ID；
5. 信号符合数据合同。

无法匹配概念的内容进入 `pendingReview`，过旧内容标记为 `ignored`。两者都不会参与热点排名。

同一创作者、同一标题、同一天的内容会按内容键去重。程序采集的新互动指标可以补充到已有人工信号上，不会制造两条重复内容。

## Codex 辅助批次

普通程序无法读取的来源会出现在 `data/collector/assist-task.json`。Codex 核对公开页面后，提交下面的数据结构：

```json
{
  "schemaVersion": 1,
  "batchId": "assisted-20260803",
  "observedAt": "2026-08-03T17:00:00+08:00",
  "method": "Codex 公开页面核对",
  "observations": [
    {
      "creatorId": "douyin-qiu-shui",
      "title": "一次性讲清 AI Agent 的 Skills",
      "sourceUrl": "https://jingxuan.douyin.com/m/video/...",
      "publishedAt": "2026-08-03T00:00:00+08:00",
      "datePrecision": "relative-day-estimate",
      "conceptIds": ["agent-skill"]
    }
  ]
}
```

批次可以通过本地接口 `POST /api/collector/assisted-batches` 提交，或者放入 `data/collector/inbox` 后运行：

```text
pnpm import:collector -- <批次文件名>
```

`data/collector/inbox/2026-08-03-codex-assisted-smoke.json` 是已通过真实导入链路验证的示例。

## 当前真实运行结果

首轮运行检查了 18 个观察源：

- 3 个 B站公开页可以程序直读；
- 15 个抖音来源转入 Codex 辅助队列；
- 0 个来源被错误标记为成功或失败；
- 程序发现 3 条页面观察，其中 1 条位于 45 天窗口内，2 条因过旧被忽略；
- Codex 辅助示例批次中的 2 条观察成功更新既有信号；
- 热点雷达在有效信号更新后自动重算。

来源是否“近期”使用更严格的 7 天窗口。当前有 15 个来源拥有 7 天内信号，3 个来源需要补充近期内容。

## 每周使用方式

建议每周运行两次：

1. 在控制台点击“运行信号采集 Agent”；
2. 查看“待更新”来源；
3. 让 Codex 按 `assist-task.json` 补充公开页面观察；
4. 导入辅助批次；
5. 检查热点雷达是否出现新的正式候选；
6. 人工选择一个候选进入 Research Agent。

## 当前限制

- 还没有建立定时触发，因此需要控制台或 Codex 主动运行；
- B站直读目前读取配置中的公开视频页，新作品链接发现仍需要搜索或 Codex 辅助；
- 抖音作品列表不由本地程序直接解析；
- 公开页面没有互动数据时，热点雷达仍只使用创作者覆盖、受众匹配和速度等已知维度；
- 平台页面结构变化时，适配器测试会失败并保留上一版可用信号，不会清空数据。
